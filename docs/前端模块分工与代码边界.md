# Elfred V28 前端模块分工与代码边界

> 代码基线：`Elfred-V28-后端交付完整包(1).zip` 中的 V28 完整项目。  
> 目标：允许团队边做产品设计、边按主页面并行开发；当前阶段不重做视觉，不处理右下角 Elfred 按钮方案。

## 1. 当前目录边界

```text
app/
├─ v27-7-app.tsx                 # 兼容入口，只做导出，不写页面逻辑
├─ v27-7-state.ts                # 共享产品状态、持久化和任务领域逻辑
├─ v27-7-data.ts                 # 五个 Agent 与初始消息演示数据
└─ v28/
   ├─ page.tsx                   # V28 路由入口
   ├─ core/
   │  ├─ app-shell.tsx           # 全局状态、页面路由、底栏和页面组合
   │  └─ screen.ts               # 所有页面共用的导航契约
   ├─ features/
   │  ├─ home/home-page.tsx      # 首页
   │  ├─ knowledge/knowledge-page.tsx
   │  ├─ messages/messages-page.tsx
   │  └─ profile/profile-page.tsx
   └─ legacy/legacy-ui.tsx       # 尚未拆分的二级流程与共享展示组件
```

`legacy` 不是废弃功能，而是“仍可运行、等待按业务域逐步迁出”的暂存层。禁止在 feature 文件中复制一份 legacy 组件形成两套实现。

## 2. 按现有分工的代码归属

### 负责人 A：首页 + 消息

- `app/v28/features/home/**`
- `app/v28/features/messages/**`
- 对应页面方案：`01-首页设计方案.md`、`03-消息页设计方案.md`

### 负责人 B：知识 + 我的

- `app/v28/features/knowledge/**`
- `app/v28/features/profile/**`
- 对应页面方案：`02-知识页设计方案.md`、`04-我的页面设计方案.md`

### 负责人 C：公共层、任务承接与集成

- `app/v28/core/**`
- `app/v27-7-state.ts`
- `app/v27-7-data.ts`
- 公共 CSS、测试、构建脚本
- 将二级页面或共享组件从 `legacy` 迁入明确业务域
- 处理跨页面状态、导航契约和合并冲突

### 暂不进入页面分工

- 右下角 Elfred 按钮及其唤醒交互仍是讨论项。
- `legacy/legacy-ui.tsx` 默认由负责人 C 管理；页面负责人需要修改其中内容时，先在需求文档写明归属，再迁出后修改。

## 3. 多人写代码的共同约束

1. 主页面只改自己负责的 feature 目录，不再把页面代码写回 `v27-7-app.tsx`。
2. 跨页面路由先修改 `core/screen.ts`，由公共层负责人合并。
3. 跨页面共享状态先修改 `v27-7-state.ts`；不允许每页建立一份含义相同的本地状态。
4. 演示数据与业务状态分开：可替换样例放 `v27-7-data.ts`，状态规则放 `v27-7-state.ts`。
5. 新建通用组件前先确认是否真的被两个以上页面使用；页面专属组件留在自己的 feature 目录。
6. 不把产品讨论项写成默认行为；分歧和 A/B Test 同时记录在共用约束和受影响页面方案中。
7. 不新增旧版本路由壳、重复 CSS 或另一套视觉系统。
8. 提交前必须通过：`npm run typecheck`、`npm test`、`npm run build`。

## 4. 当前已确认的页面约束

- 首页是综合动态首页；三时段简报是第一主内容，并按时间更新当前卡片。
- 首页包含五个子 Agent 与 Agent 朋友圈；五个 Agent 的信息源、记忆和 Skill 彼此隔离。
- 消息列表主体只是真人私聊和真人群聊，分类为“全部 / 私聊 / 群聊”。
- 自己的 Person Agent 与五个子 Agent 不作为联系人；Agent 在会话内被唤醒，私密对话只对本人可见。
- 社区只保留真人主体。
- `@` 与快捷入口是 A/B Test；Agent 对话“默认半屏、可展开全屏”仍是讨论项。

## 5. 下一轮拆分顺序

1. 把首页专属的朋友圈卡片、三时段简报和任务播放器迁入 `features/home/components`。
2. 把知识页专属的能力卡、理解度弹层迁入 `features/knowledge/components`。
3. 把消息搜索、个人聊天、群聊及 Agent 私密唤醒界面迁入 `features/messages`。
4. 把个人主页分享、编辑和设置迁入 `features/profile`。
5. 最后按业务域拆分任务、社区、初始化流程，并逐步清空 `legacy`。

每迁出一组功能，都要保持单一实现并重新跑三项门禁；不要一次性重写全部二级页面。
