# 需要同事那边加的东西：让「我的 Elfred」对话真的能用

## 现象（可复现）

打开 `http://127.0.0.1:3100/v28` → 进「我的 Elfred」对话，屏幕中间是
**"内容不存在或当前不可访问"**，输入框发不出任何消息。

## 原因（查证过，不是猜）

1. 前端有 **5 处**跳 `go({ name: 'chat', id: 'elfred' })`：
   `core/app-shell.tsx:682`、`knowledge-page.tsx:407`、`knowledge-page.tsx:949`、
   `memory-page.tsx:125`、`profile-page.tsx:343`，
   旧 UI 里还有 `legacy-ui.tsx:1797 / 2588 / 6695 / 6937`。
2. 但服务端**没有产生 id 为 `elfred` 的会话对象**。`objects.type='conversation'` 在整个库里
   只在两处被创建：
   - `social.mjs:34` 好友申请通过 → 私聊（`kind:'direct'`，和另一个真人）
   - `social.mjs:55` `conversation.create` → 群聊（要求 1–30 个好友账号）
   —— 没有"和本人 agent 的会话"这条路径，也没有"按指定 id 建会话"的能力。
3. 而 `message.send`（`social.mjs:96`）和 `draft.save`（`social.mjs:115`）
   第一行都是 `member(input.id)`，**必须先有会话成员资格**；
   `assist.create`（`social.mjs:126`）同样要求 `member(conversation_id)`。
   所以哪怕把文字塞进输入框，也发不出去。

## 需要加什么（二选一，都很小）

**方案 A（推荐）：加一个"确保个人 agent 会话存在"的命令**

```
conversation.ensure_personal  →  { id }
```

- 幂等：同一个人重复调用返回同一个会话；
- 会话归属本人、`kind: 'direct'`（或新增 `kind: 'owner'`），成员只有本人；
- 前端把那 5 处 `id: 'elfred'` 换成"先 ensure，再用返回的 id 跳转"即可。

**方案 B：让对话页接受预填**

`screen.chat` 加一个可选参数（例如 `prefill` / `contextId`），`ChatPage` 读它初始化输入框；
同时**仍然需要方案 A**，否则会话不存在、消息还是发不出去。

## 我们这边的接口**已经写好了**（2026-09-25，等这个命令）

第二页的「用它做一件事」已经能算出**任务契约**：这条能力《X》的步骤、用户逐条定下的规矩、
验收用例、以及从记忆中枢召回的相关条目（`GET /page2/contract?skill=&goal=`）。

调用链也已经按"先要会话、再把契约写进输入框"的顺序实现了
（`app/v28/features/knowledge/skill-launch.ts` → `ensurePersonalConversation()`）：

1. 会话已存在（`objects.conversation` 里有 `id === 'elfred'`）→ 直接用；
2. 没有 → 调 `conversation.ensure_personal`；拿到 id 就继续；
3. **拿不到就如实退回**（`reason: "need_conversation"`），调用方走原来的行为，
   不假装已经带进场、也不弹错误打断用户。

所以你那边**只要加上这条命令，我们一行都不用改**就会自动走通：
点卡片 → 契约写进对话输入框 → 用户补一句要做什么 → agent 按这条能力做
→ 做完验收 → 结果自动回到第二页更新这条能力。

（`ensure_personal` 建议幂等、返回值就一个 `{ id }`；参数 `id` 传 `'elfred'` 就用它，
不传就自己生成、之后每次返回同一个。）
