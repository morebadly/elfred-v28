## 原稿的具体问题

共同场景：想做一个轻量项目，但方向尚未明确。

| 顺序 | 发问者 | 原始问题 | 具体选项 |
|---|---|---|---|
| 1 | Person Agent | 你现在最需要解决什么？ | 找到方向／比较方向／做出成果／找人合作／推进执行 |
| 2 | 探索 | 你希望从哪里寻找项目方向？ | 近期兴趣／已有能力／身边问题／外部趋势与机会 |
| 3 | 参谋 | 选择方向时，你最看重什么？ | 感兴趣／能做出来／有实际价值／风险低／有发展空间 |
| 4 | 创作 | 你希望先形成什么结果？ | 概念方案／页面原型／内容作品／可运行的小产品 |
| 5 | 连接 | 这个项目需要别人参与吗？ | 自己完成／先听取建议／寻找合作者／寻找用户或资源 |
| 6 | 执行 | 你希望以什么节奏开始？ | 今天完成第一步／本周做出原型／先调研再决定／暂时只建立待办 |
| 7 | Person Agent | Agent 可以主动到什么程度？ | 我问时再回应／重要时提醒／可以主动提出建议／低风险事项可以先处理 |
| 8 | Person Agent | 涉及联系他人或公开发布时，可以做到哪一步？ | 只向我推荐／整理资料／生成待确认草稿／每次先问我 |

每题均有“都不符合／暂时不确定／以后再说”；原文要求的出口统一应用到全部题目。没有将兴趣、职业、人格或完整五系统问卷设为必填。

## 浏览器实测记录

使用本地验收账号完成八题：做出成果 → 已有能力 → 暂时不确定 → 页面原型 → 自己完成 → 本周做出原型 → 重要时提醒 → 生成待确认草稿。

- 开始页说明 Person Agent、五个 Agent、信息用途；题目为选择按钮，无主动输入、文件上传。
- 逐个聊切换一起聊，原有选择保留；完整八题后显示逐项理解卡，不确定项保持理解不足。
- 稍后继续返回首页，四个导航可见；重新打开保留八项选择、组织方式及当前阶段。延期未完成账号的导航恢复另有产品回归覆盖。
- 确认选择并存入收件箱后，显示真实草稿、收件箱和任务入口；从收件箱打开任务，状态为草稿，执行仍需本人确认。
- 修改“选择方向时，你最看重什么”为“风险低”后直接回理解卡，不强迫重新答后续五题；重新确认后，明确提示旧任务仍使用创建时选择。
- 问题卡截图核对：当前题目与出口可见，自动定位有效，固定顶部不遮挡题目；已保存阶段精简为任务承接卡。
- 原有首页五个 Agent 和三时段任务计数保留；初始化上下文只补入已有区域。收件箱优先展示保存时的事项名称和摘要，避免把完整执行约束当作列表标题。

本次仅创建本地验收任务草稿，没有调用真实模型，没有发送真人消息或发布社区内容。无 API Key 的执行边界由集成测试覆盖。
