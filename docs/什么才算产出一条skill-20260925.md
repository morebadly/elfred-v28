# 什么才算产出一条 skill（规则 + 现状定性）

## 规则（已落地）

**一次指正不产 skill。**同一条能力**做过 ≥2 次**才固化 —— 一次只是事件，重复出现才算"做法"。
这条对应产品原话："跟 agent 做事的过程中产出 skill"；反过来"随便做一件事就长出一条 skill"
是错的（用户实测指出过）。

落地位置：`app/bridge.py` → `sync_memories()` 的反馈分支。

- `taskCounts[(用户, 能力 id)] < 2` → 这次指正**只作为记忆的原料**写进中枢（EMOS），
  **不写 skill**，并在 `bridge_marks` 里记下"这条能力只做过 N 次，不足 2 次不固化"。
- `≥ 2` → 才走 `apply_feedback`：把指正归一成"用户定下的规矩"，写进这条 skill 的新版本
  （SKILL.md / workflow.json / provenance / examples / tests 七件套），并写记忆。

实测（`tools/page2-checks/loop-check.mjs`，13/13）：
第 1 次驳回并指正 → 规矩仍是 0 条、记忆进了 1 条；第 2 次跑完再指正 → 规矩 1 条，
而且**下一次的任务契约里带着这条新规矩**。

## 样板数据也一并清了（同日）

产品口径追加：**不要样板数据**。所以：

- `seed.py` 种的那批（3 张示例卡 + 成果/记忆/素材/文档/关系/快照，共 **48 行**）已全部删除，
  工具是 `tools/reset_sample_data.py --apply`（只动指定 user_id，带预演）；
- `SEED_ON_START` 在 `.env` 与 `.env.example` 里都改成 **false** —— 不再每次启动种回来。

清完之后实测：`demo` 卡 0 / skill 0 / 成果 0，理解度回到新用户的 **10%**（不确定度 100%）。

连带的：有三条探针原来**压着"demo 必须有数据"这个基线**（`identity-check` 的旧行为断言、
`sheet-footer-check`、`profile-ability-honors`）。它们都改了：
前者的断言改成验**身份回退**（不带头时后端仍按 `DEMO_USER_ID` 算、请求正常返回），
后两者改成**用一次性新账号 + 自己建一张卡**（不在任何账号上留测试残留）。
