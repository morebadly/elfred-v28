# 后端打通 · 2026-09-25

## 一句话

同事那两页（首页/第三页）**验收过的成果**，现在会自动变成我这边的成果：
能力卡组、知识库、理解度、能力雷达、第四页动态、勋章，全都跟着动。

## 为什么之前不通

前端融合之后，两边仍然是**各写各的库**：

| | 他的（elfred-v28） | 我的（elfred-page2-api） |
|---|---|---|
| 存哪 | `.elfred-data/elfred.sqlite` | `local.db` + EMOS |
| 一行数据长什么样 | `objects(id, type, owner, data JSON)` | `capabilities / evidence / evidence_impacts` |
| 谁知道谁 | 完全没有引用 | 完全没有引用 |

所以用户在首页跟 Elfred 做完一件事并验收，第二页之前**什么都不会变** —— 那只是把界面拼在一起。

## 怎么接的

新增 `app/bridge.py`，做一个**翻译层**，不用两边改数据结构：

| 他那边 | 我这边 | 说明 |
|---|---|---|
| `outcome` 对象（`task.accept` 时创建，`verdict=accepted`） | 一条**成果** `Evidence` | 只认"本人验收过"的，run 跑完不算 —— 和第二页自己那条链同一个口径 |
| `task.data.capability`（kind / system / name / purpose） | 一张**能力卡** `Capability` | 卡的身份用 `capability.id`（`execute-0`），不用名字：改名不会断历史 |
| `system`（explore/advise/create/connect/execute） | 维度（洞察/判断/表达/链接/交付）+ 子 Agent 名（探索/参谋/创作/连接/执行） | 我的 `algorithms.AGENT_LEVELS` 用的本来就是这五个名字，不是硬凑 |
| `knowledge` 产物（验收时生成的正文） | 成果的 `summary` | 取不到正文就留空，不拿模板句凑 |

分数、等级、权重**一个都没新造**：走 `scoring.update_score / score_of / read_level`
和 `algorithms.evidence_weight`（本人验收 = 权重 1.2），和第二页自己跑 skill 是同一条链。
所以「他做的事」和「我做的事」在理解度、雷达、勋章里是同一套账。

三条纪律：
1. **只读他的库**：整层只有 `SELECT`，不写、不改、不删他的数据。
2. **幂等**：用 `outcome.id` 当 `Evidence.source_id`，重复同步不会重复计分。
3. **不编**：查不到账号的用户不落；取不到正文就留空。

跑法：后台任务每 20 秒扫一遍（`jobs.py`），也可以手动 `POST /page2/bridge/sync` 立刻同步。
开关是 `ELFRED_BRIDGE_DB`（指向他 sqlite 的路径），**不配就整层不生效**。

## 前台看到什么

用户在他那边验收一条之后（20 秒内，或手动同步）：

- **能力卡组**：多一张卡（名字就是他用的那个能力，比如「执行规划」），维度、分数、成果数都是真的
- **知识库**：今天那条成果出现，标题就是他写的那句目标
- **能力洞察**：雷达上对应那一维有值，综合分跟着变
- **理解度 / 第四页**：对齐阶段、动态、勋章跟着推

## 顺手修的两个真 bug（都是被这次改动逼出来的）

1. **能力卡 id 不带用户维度**（`ingest.ensure_card`）。
   卡 id 原来是 `cap-{skill 名}`，单用户不炸、**第二个人进来就炸**：
   同一个能力（他的 `execute-0`）解析成同一个 id，`session.get` 直接拿到别人的卡，
   于是这个人的成果记到那个人的卡上、把那个人的分也改了。实测第二次跑就撞上了。
   改法：老 id 写法不动（改了会把 demo 现有的卡全变成新 id、多出一批重复卡），
   只在"这个 id 被别的用户占了"时换成带用户前缀的 id。老数据一字不动，新人各归各。

2. **知识库那张卡被长标题顶穿**。
   卡是固定高度的一行布局；演示数据的标题很短（"跑了一次《文档要点摘要》"）看不出来，
   桥接过来的标题是用户写的整句目标，折成三行压到副标题上（截图里字叠成一团）。
   已在 `knowledge.module.css` 里给标题加单行省略，并在探针里**量**出来（标题 h21、没压行）。
