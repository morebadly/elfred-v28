按《循环设计-任务契约与记忆中枢》执行。**不破坏功能、不破坏前端**：第二/四页的版式、入口、

## 一、任务契约（记忆 + 能力 → 一次做事的执行条件）

- 新增 `app/contract.py` + `GET /page2/contract`：把这条 skill 的**步骤 / 用户定下的规矩 /
  输入输出 / 验收用例**，加上从记忆中枢召回的相关条目，组装成一次任务的执行条件。
- 「用它做一件事」从**死的**变成**真的**：
  - 原来：只往前端本地状态塞一条草稿（`state.tasks` 每次 snapshot 刷新都被 `projectState`
    重建 → 十几秒内蒸发），"用哪张 skill"写进没人读的 `pendingSkill`；跳到对话页，
    而那个对话**连会话对象都没有**（`draft.save` / `message.send` 都要求先有会话成员），
    屏幕上只有"内容不存在或当前不可访问"。
  - 现在：写一句"这次要做什么" → 取契约 → **真建一条任务** → 去那条任务。
    契约落在他那边的 `criteria` / `constraints`（一等字段，`provider.generate` 会把整个
    goal 对象 JSON 进 user message，模型一定看得到）。
- 拿不到契约不硬塞：如实说"这次没取到做法"，用他原来的默认值；没有 runtime（我那边单独跑）
  时退回原来的本地草稿行为，行为一字不变。

## 三、顺手修的四个真 bug（都是被这次改动逼出来的）

1. **带 `paId` 的 17 个接口实际按 `None` 查**（我上一轮改身份时引入的）：解析后的值只写回了
   `user`，而函数体用的是 `paId`。记忆库/对齐/触发器这些接口全部查不到人。已修。
2. **能力卡 id 不带用户维度**：第二个人进来会拿到第一个人的卡，成果记到别人头上。已修。
3. **`skills-out` 目录所有人共用**：两个人各产一条同名能力会互相覆盖（frontmatter 的
   `user_id` 被后来者改掉）。现在非默认用户带用户前缀。已修。
4. **契约按 skill 目录名找**：前端手里是卡片标题，找不到就静默退回默认值 ——
   任务建出来了但 skill 没进场，**表面看是通的**。现在按标题/目录名都认，且**只在该用户自己的
   skill 里找**（第一版用了全局查找，新账号直接拿到了别人产的同名能力）。已修。
