# 调研：① 维度分怎么算（人 ≠ skill）② 空态那份问卷用什么

> 本轮**只调研、不改代码**。所有链接都是我这轮真打开过的（GitHub API / arXiv 搜索页）；
> 打不开的来源（Wikipedia、HuggingFace、搜索引擎、raw.githubusercontent）我没有采信。

## 一、问题诊断：现在把"卡的分"当成了"人的分"

现状（`app/insight.py` → `axes_now()`）：

```python
# 该维度下所有卡的分数，按卡的成果数加权平均
out[name] = Σ(card.score × max(1, card.evidence)) / Σ max(1, card.evidence)
```

卡的分（`scoring`）说的是"**这条 skill 可靠不可靠**"：基线 60、被确认的成果把它推高、被指正会退回去。
把它直接当人的维度分，有三处不对：

1. **主体混了**：卡是资产，人是人。一条做得好的 skill 不等于"这个人这一维强"——比如 agent 自己跑得很好、用户只按了验收。
2. **能被"非能力"因素推高**：多建几条卡、多验收几次，维度分就上去了，哪怕这些事都是随手的小事。
3. **没有难度、样本量、时间三个维度**：做 10 件小事和做 1 件难事，现在的算法只看"卡的分"；样本少也不打折，久了也不会掉。

## 二、候选机制（都带实现与出处）

| 机制 | 解决什么 | 可用实现（许可） | 论文/证据 |
|---|---|---|---|
| **项目反应理论 IRT**（2PL 及多分面） | 把"**事情难度 b / 区分度 a**"和"**人的能力 θ**"**分开估**；样本少时 θ 的不确定度大 | `eribean/girth`（MIT，★126，Python，昨天还在更新） | arXiv 2607.25257 *Laplace-PSN-IRT*（讲 IRT 的**不确定度量化**）、2607.06905（IRT 标定） |
| **多概念 Elo**（Multi-Concept Multivariate Elo） | 一次表现同时更新**多个维度**的能力估计；增量、在线、便宜 | `atomflunder/skillratings`（Apache-2.0，Rust，含 Elo/Glicko-2/TrueSkill）、`wdm0006/elote`（MIT，Python，多算法对比）、`DataWraith/bbt`（MIT，贝叶斯技能评分） | arXiv 2403.07908 *Adaptation of the Multi-Concept Multivariate Elo Rating System to Medical Students Training Data*（**和我们"五维 + 每次更新"几乎同构**）、2204.01805（Elo 用于教育评估） |
| **贝叶斯知识追踪 BKT / KT-IDEM** | 把"掌握度"当**隐状态**，带 learn / forget / guess / slip 四个概率；**可升也可降** | `CAHLR/pyBKT`（MIT，★280，支持**逐题难度**与逐资源学习率） | pyBKT README 引用 Pardos & Heffernan 2011 *KT-IDEM: Introducing Item Difficulty to the Knowledge Tracing Model* |
| **TrueSkill / Glicko**（σ 是显式的） | 输出天然带"**我有多不确定**"，正好对应我们界面上的"未知/不确定" | `skillratings`(Apache-2.0)、`elote`(MIT)、`bbt`(MIT)。⚠️ `sublee/trueskill`（★803）的许可文件显示 **Caution/未声明** → **不要依赖它** | — |
| **FSRS / 半衰期衰减** | "很久没做就会退" 这件事有成熟模型 | `open-spaced-repetition/py-fsrs`（MIT）、`fsrs-rs`（BSD-3）、`awesome-fsrs`（CC0） | 上一轮理解度已经用了同族思路（半衰期 30 天） |

**一个直接的旁证**：arXiv 2609.21154 *CoLearn: An Agentic Tutor that Learns its Learner in a Human–AI Co-Learning Loop*
——"AI 在学习它的学习者"，就是我们要做的事；它的机制正是"每次交互更新对用户的估计"。

## 三、推荐方案（问题一）

**核心：维度分是对"这个人这一维"的估计，卡的分只是其中一个观测。**

```
每个维度 d 维护一个后验 (θ_d, σ_d)   // 均值 = 估计，σ = 不确定度

先验：来自问卷自评（见问题二）        θ_d ~ N(自评值, σ_先验大)     // 自评不可信 → 方差给大

每次"被验收的成果" e（挂在维度 d 的卡上）更新：
    θ_d ← θ_d + K_e · (y_e − θ_d)          // Elo/贝叶斯更新的形式
    σ_d ← σ_d · (1 − K_e)  且  下限 σ_min   // 样本变多 → 不确定度变小
其中
    K_e ∝ 1/(σ_d² 的当前值 + 噪声) × w_e      // 样本越多、σ 越小，单次影响越小
    y_e = 这次表现分（现有 outcome_from_run）
    w_e = 证据权重，必须**按来源分档**：
          外部可核对结果（老师批改/对方回应/实际被采用） 1.0
          本人验收                                       0.35（只是"能用"，不是"做得好"）
          本人亲手做过 / 明确指正过                      + 额外加成
          纯 agent 代做、用户只点了一下                    再打折
    b_e = 事情难度（先粗分三档：小/中/大），用于把 y_e 做难度校正（IRT 的 b）

时间衰减：            每过一个半衰期（暂定 30 天没有新证据）σ_d 放大、θ_d 向先验收缩
```

对外给三个值，界面才能说人话：

### 参数表（每个符号是什么、初值怎么定）

| 符号 | 含义 | 初值 / 取法 |
|---|---|---|
| `θ_d` | 维度 d 上"这个人"的能力估计 | 新用户 = 问卷自评值；没做问卷 = 不参与（该维显示"未知"） |
| `σ_d` | 这个估计的**不确定度** | 只有自评：大（如 12）；有 1 条真实证据后开始收窄；下限 `σ_min`（如 3） |
| `y_e` | 第 e 条证据的**表现分** | 直接用现有 `algorithms.outcome_from_run()`（确认/指正/外部结果） |
| `w_e` | 这条证据的**权重** | 分档：外部可核对 1.0 ／ 本人验收 0.35 ／ 本人亲手或明确指正过 ×1.2 ／ 纯 agent 代做 ×0.7 |
| `K_e` | 这条证据**改多少** | `K_e = w_e · σ_d² / (σ_d² + τ²)`（τ 是观测噪声，先取 8）；样本越多 σ 越小 → K 越小 → **边际递减** |
| `b_e` | 事情**难度** | 先粗分三档（小/中/大 → 0.9 / 1.0 / 1.15），难度校正：`y_e' = 50 + (y_e − 50)/b_e` |
| `H` | **半衰期** | 暂定 30 天：`H` 天内没有新证据 → σ 放大、θ 向先验收缩（"久了会退"） |
| `τ` | 观测噪声 | 先取 8（与 `σ_min`、`SIGMA0` 同一量级），后面用真实数据拟合 |

边界（样本少怎么办）：**样本数 < 3 时，界面不显示 `θ`，只显示"样本不足（还差 N 条）"**；
有自评但没证据时显示"自评"，并把它画成淡色/虚线。三条都**不允许**混进"已验证"的样式里。

| 字段 | 含义 | 界面口径 |
|---|---|---|
| `value` | 当前估计（θ） | 有真实证据才画**实线** |
| `lower` | 置信下界（θ−1.5σ） | 保守值；与卡的分同一坐标系，方便对照 |
| `samples` / `source` | 有几条证据、来自自评还是证据 | **样本少 / 只有自评 → 标"自评"或"样本不足"，不冒充成绩** |

**为什么比现在好**：主体分开（skill ≠ 人）、难度参与（难事 > 小事）、来源参与（外部 > 自评）、样本量与时间参与（少不吹牛、久会退）、而且每次更新是**可解释的**（能说清这次为什么涨/降）。

**与现有代码的接法**：`axes_now()` 换成 `axes_from_evidence(session, user)`；卡的分仍由 `scoring` 管、不动；
`axis_view()` 输出加上 `source / samples / uncertainty`；`/insight/abilities` 保持字段兼容、
新增字段前端逐步用。问卷自评进 `dimension_baselines` 表当先验。

## 四、问卷（问题二）

### 4.1 先说结论：**题库可以合法用，而且是公有领域**

| 候选 | 许可 | 题量 | 语言 | 适配度 |
|---|---|---|---|---|
| **`NeuroQuestAi/five-factor-e`**（PyPI 上也叫 five-factor-e） | **MIT** ✅ | 内置 **120 题 / 300 题**两套；1–5 计分；带常模 `norm.py`（含性别/年龄校正） | JSON 多语言：`en-us / es-es / pt-br` —— **没有中文** | **最适合当引擎**：题库 + 计分 + 常模都现成 |
| `kholia/IPIP-NEO-PI` | 仓库**未声明许可** ❌（代码不可直接用） | IPIP-NEO-120 | 英文 | 只能当**题目来源参考** |
| `PicoAaron/personality-tests` | **GPL-3.0** ❌（传染性） | Mini-IPIP、NEO-PI-R 10 题 | 英文 | 只能当参考，不能进我们的产品 |

**关键事实（决定了能不能用）**：`five-factor-e` 的 README 明写——
> "The International Personality Item Pool (IPIP) is a **public domain** collection of items for use in personality tests."

也就是说：**IPIP 的题目是公有领域**，我们可以自由改写、翻译、商用；只有具体仓库的**代码**受它的许可约束
（`five-factor-e` 是 MIT，可以用；GPL 那个不能）。

顺带查过中文：GitHub 上**没有**现成可用的中文大五题库（搜到的都是 IP 地址库、政论库、MBTI 趣味测试）。
所以中文题目要么我们按公有领域题目自己翻译，要么自研——**都合法**。

### 4.2 但要注意：Big Five 测的是**人格**，不是**能力**

我们五维是 判断 / 洞察 / 交付 / 表达 / 链接，Big Five 是 开放性 / 尽责性 / 外向性 / 宜人性 / 情绪稳定性。
映射关系强弱不一样：

| 我们的维度 | Big Five 里最接近的 | 映射强度 |
|---|---|---|
| 洞察 | 开放性（好奇、想象、审美） | 强 |
| 交付 | 尽责性（条理、自律、追求成就） | 强 |
| 表达 | 外向性（主张、健谈） | 中 |
| 链接 | 外向性 + 宜人性（亲和、合作） | 中 |
| **判断** | 尽责性的"审慎" + 情绪稳定性，**但没有直接对应** | **弱** → 需要自研题补 |

**所以推荐"混合"而不是"直接用"**：以 IPIP 公有领域题目为底（负责心理测量学上站得住的那部分），
再补 **3–4 道自研题**把"判断"这一维撑起来。

### 4.3 打分与偏差（两条论文证据）

- **自评不可信，只能当先验**：arXiv 2606.00860 *GenPT: Beyond Self-Report for Reliable LLM Psychometrics* ——
  自评（self-report）本身可靠度有限。这正好支撑我们的设计：**自评给先验、真实证据改后验**。
- **社会期许偏差要处理**：arXiv 2602.17262 *Quantifying and Mitigating Socially Desirable Responding* ——
  用"**被迫选择**"（graded forced-choice / 二选一或多选一）能显著降低"我想显得更好"带来的偏差。
  → 我们每题给**选项**（不是 1–5 打勾），比纯 Likert 更抗偏差。
- **反向计分**：IPIP 的题本来就是正/反向项混合（例如"Worry about things." 反向于情绪稳定），照它的 key 走。

### 4.4 题目草稿（12 题 / 每维 2 题 + 2 道反向题）

> ⚠️ **这一节是当时的草案，最后没有采用** —— 落地的是**混合方案 (B)**（IPIP 原题 16 道 + 自研「判断」6 道，共 22 题），
> 并且**删掉了两道"校准题"**（改成用 IPIP 自带的正/反向项估作答一致性）。见文末第五节。

选项统一三档（偏高分在右），**不自报"我多强"，只问"你通常怎么做"**：

| # | 维度 | 题目 | 选项 |
|---|---|---|---|
| 1 | 判断 | 别人跟你争一件事，你先做什么 | 先说我的看法 ／ 先要证据 ／ 先问清对方在说什么 |
| 2 | 判断 | 要下结论但信息不全时 | 先按经验定 ／ 标出哪些是猜的 ／ 直接说结论 |
| 3 | 洞察 | 遇到不熟的领域 | 基本不碰 ／ 需要才查 ／ 习惯先摸一遍 |
| 4 | 洞察 | 别人给你一堆零散信息 | 先存着 ／ 先归类 ／ 顺手找出其中的模式 |
| 5 | 交付 | 手上的事什么时候算"做完" | 我觉得差不多 ／ 达到事先说好的标准 ／ 达标且留有记录 |
| 6 | 交付 | 计划被打乱时 | 先改计划 ／ 先保交付底线 ／ 先告诉相关的人 |
| 7 | 表达 | 你要把一件事讲给别人 | 按发生顺序讲 ／ 先说结论 ／ 先问对方想听哪部分 |
| 8 | 表达 | 对方没听懂 | 重复一遍 ／ 换个说法 ／ 画个例子 |
| 9 | 链接 | 需要找人帮忙时 | 直接开口 ／ 先想清要什么 ／ 尽量自己扛（**反向**） |
| 10 | 链接 | 跟人打交道之后 | 就事论事结束 ／ 顺手记一下对方的偏好 |
| 11 | —（反向/校准） | 我很少拖到最后一天才动手 | 不同意 ／ 一般 ／ 同意（**反向计分，用来校准**） |
| 12 | —（反向/校准） | 我更愿意别人替我把结论定下来 | 不同意 ／ 一般 ／ 同意（**反向计分**） |

映射：每维 2 题（3 档 → 1/2/3 分）取平均 → 归一到一个**保守区间**（例如 45–70），
并标 `source=self_report`；第 11/12 题用于估计"答题是不是在自我美化"，偏高时把自评初值的权重压低。

## 五、落地结论（2026-09-26 晚 · 已实现）

用户拍板后的实际做法，以及和上面推荐的差异：

1. **直接上 (B)，不先做 (A)**：题库 = IPIP 原题 16 道（洞察←开放性 / 交付←尽责性 /
   表达←外向性 / 链接←宜人性，各 4 道，正反向各半）+ **自研情景题 6 道**补「判断」，共 **22 题**。
   IPIP 是公有领域，中文由我们翻译；翻译时保留了**方向键**（`key: 1/-1`）。
2. **不用 IPIP 的情绪稳定性（N）那 4 题**：我们量的是"做事的能力"，不是人格诊断；
   拿"我常有情绪波动"去定「判断」，用户看不懂分数是怎么来的。
3. **删掉"校准题"**：校准改由 **IPIP 自带的正/反向项**承担 —— 一路点"同意"的人在正/反两侧
   会自相矛盾，这个矛盾量就是 `guard`（只用来放大起点的 σ）。用户原话是
   "不能有什么自评不进入综合分这种东西，我不知道存在的意义是什么" —— 所以**不额外占题位**。
4. **"自评先验不进综合分"这条被否掉**：改成 **测完就有一张起点图 + 综合分**（起点区间 22–52，
   整体压在卡片基线 60 之下），起点**计入**综合分；之后按真实表现升、判错与长期不用降。
   第四条"对外给 θ 还是 θ−1.5σ"：两个都给（`value` / `lower`），界面默认用 `value`（起点必须是可读的数字）。
5. **一条实测出来的 bug**：`POST /evidence` 原来把每条成果都写成"计为 1 次外部验证"，
   等于"自己点一下 = 外部证实"。现在统一写 `权重 {w}`，人的维度分按这一档给权重。
