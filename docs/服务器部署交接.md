# Elfred V28 服务器部署交接

生产地址：`http://111.230.26.68/v28`。服务器以 `/www/wwwroot/elfred-mobile/current` 指向当前发布目录，应用由 PM2 的 `elfred-mobile` 进程运行。用户数据和 `.env.local` 独立保存在 `shared` 与既有私密配置中，**不要删除或覆盖它们**。

## 同伴需要的权限

已创建独立账号 `elfred-deploy`，并安装单独的 SSH 公钥。它可上传文件到 `/home/elfred-deploy/incoming`，且仅被授权以 sudo 运行服务器上固定、由管理员持有的 `/usr/local/sbin/elfred-deploy-server.py`。管理员应通过安全渠道把对应 **私钥文件** 交给同伴；同伴不要把私钥、模型 API Key 或 `.env.local` 放进仓库、聊天群或发布包。拿到私钥后，Linux/macOS 上先执行 `chmod 600 SSH_KEY`。如要撤销访问，管理员删除该账号的授权公钥和 `/etc/sudoers.d/elfred-deploy`。

## 每次发布

在本地克隆仓库 `https://github.com/morebadly/elfred-v28`，确认要部署的提交已经合入 `main`，并在项目根目录执行：

```sh
git pull --ff-only origin main
npm ci
npm test
npm run typecheck
npm run test:runtime
npm run build:local
python scripts/package-release.py elfred-release.tar.gz
```

Windows 上的 Python 命令可以换成 `py -3`。运行时测试在受限 Windows 沙箱里可能因为临时 SQLite 文件无法重命名而失败；此时应在正常终端或 Linux 构建机重跑，不能据此省略其他失败。

然后上传打包文件和部署脚本，并在服务器执行：

```sh
scp -i SSH_KEY elfred-release.tar.gz elfred-deploy@111.230.26.68:/home/elfred-deploy/incoming/
ssh -i SSH_KEY elfred-deploy@111.230.26.68 'sudo -n /usr/bin/python3 /usr/local/sbin/elfred-deploy-server.py /home/elfred-deploy/incoming/elfred-release.tar.gz 20261013-your-change'
```

每次更换唯一的发布标签。服务器上的固定脚本会检查包、备份 SQLite 和私密配置、复用或安装依赖、切换 `current`、重启服务并检查应用与记忆服务；启动失败会恢复原版本。仓库中脚本如有变更，应由管理员先审核并更新服务器上的固定副本；同伴不能自行替换该副本。不要把 `.env.local`、`node_modules` 或用户数据库上传到 GitHub。部署后打开 `http://111.230.26.68/v28`，并检查 `http://111.230.26.68/api/elfred/health`。

如果需要手工回滚，先暂停新发布，再请服务器管理员把 `current` 指回上一个 `releases` 目录并重启 `elfred-mobile`。每次发布的备份位于 `/www/backups/elfred-<发布标签>`，不要随意恢复数据库覆盖发布后的新用户数据。
