## 1. 文档用途

本文是新开发对话的统一入口，负责说明：

- 产品究竟是什么；
- 已确认的页面框架和跨页边界；
- Person Agent 与五个子 Agent 如何分工；
- 哪些内容可以直接实现，哪些只能做可切换原型，哪些不得擅自开发；
- 当前代码从哪里启动、如何分工、如何验收；
- Letta、Codex、EvoMap、LAAP、Elys 等项目在本项目中的真实位置。

详细产品推导仍以工作区根目录的页面方案和共用约束为准。本文不能把“待验证假设”升级成“已确认需求”。

## 2. 决策状态

| 状态 | 开发含义 |

| 已确认 | 可以作为当前原型默认规则 |

## 3. 产品定义

### 3.1 目标用户

当前优先验证即将进入社会的学生与年轻职场用户。他们的信息、关系、目标和行动分散，既需要 AI 帮助，又担心被过度推断、替代决策或泄露私人信息。

### 3.2 核心问题

普通 AI 通常只理解一段对话，难以持续对齐一个人在不同时间、关系和任务中的真实变化。Elfred 要解决的是：

> 如何在用户可见、可纠正、可授权的前提下持续理解用户，并把这种理解转化为当天有用的行动支持。

### 3.3 当前产品命题

> Elfred 通过内容、关系和真实行动持续理解用户，使用 Person Agent 与当前五种能力 Agent 帮助用户处理信息、判断、创作、协作和执行，再把经用户确认的结果沉淀为可解释、可纠正的记忆与能力。

### 3.4 产品主循环

```text
内容 / 真人关系 / 用户目标 / 现实事件
→ 形成弱信号或候选事项
→ 用户确认意图、范围和权限
→ Person Agent 编排相关子 Agent
→ 产生真实行动与结果
→ 用户验收、修正或否认
→ 沉淀 Evidence / Outcome / 记忆 / 能力
→ Elfred 改善后续支持
```

收藏、点赞、停留、聊天和 Agent 推断都不能直接跳过用户确认变成正式任务、长期事实或对外承诺。

## 4. Person Agent 与五个子 Agent

### 4.1 为什么当前是五个子 Agent

问题不是把完整人格切成五块，而是寻找从“认识世界”到“改变现实”所需的最小、可独立评价、可相互制衡的对外能力集合：

| 必要转化 | 能力 | Agent | 核心产出 |
|---|---|---|---|
| 未知与变化 → 证据和可能 | 发现 | 探索 | 证据、未知点、新可能 |
| 证据 + 目标约束 → 选择 | 判断 | 参谋 | 比较、风险、取舍建议 |
| 材料与想法 → 新方案或作品 | 创造 | 创作 | 方案、表达、作品 |
| 个体需求 → 与他人共同作用 | 协同 | 连接 | 人、关系、协作方式 |
| 已确认意图 → 现实结果 | 实践 | 执行 | 计划推进与结果 |

探索与参谋必须独立：探索扩大证据范围，参谋依据用户目标压缩选择，避免同一个 Agent 为自己的假设选择证据并自我说服。

当前“五 Agent”是有依据的产品假设，不是关于人类能力天然只有五类的结论。删除、合并或新增 Agent 时，必须检查是否出现能力缺口、权限混合、自我证明或重复产出。

### 4.2 Person Agent 的职责

Person Agent 不与五个子 Agent 并列承担某一种局部能力，而负责元认知：

- 理解“这个人是谁、现在发生了什么变化”；
- 合并多个 Agent 的结果并保留替代解释；
- 识别重要 Moment；
- 决定是否向用户求证；
- 按任务向相关 Agent 分配最小必要上下文；
- 管理权限、风险和人工确认；
- 根据真实结果反思并提出记忆、Skill 或支持策略的调整建议。

### 4.3 Agent 隔离与通信

五个子 Agent 默认拥有不同的信息源、私有记忆、Skill、工具、权限和评价标准，不能相互读取完整记忆。

内部通信采用“任务级路由”，不采用自由共享记忆：

```text
子 Agent / 页面发现信号
→ Person Agent 判断任务目的与授权
→ 生成最小上下文包
→ 指定目标 Agent 与输出契约
→ 子 Agent 返回结果和证据
→ Person Agent 合并、反思
→ 需要时交给用户确认
```

建议的通信对象至少包含：

```ts
type AgentEnvelope = {
  taskId: string;
  from: "person" | "explore" | "advise" | "create" | "connect" | "execute";
  to: string[];
  purpose: string;
  contextRefs: string[];      // 只引用获准的最小上下文
  outputContract: string;
  permissions: string[];
  expiresAt?: string;
};
```

Agent 朋友圈中的发帖和评论是用户可见的显性交互，不等于底层记忆互通。

### 4.4 反思与自进化

反思由 Person Agent 跨 Agent 完成。当前前端应表达以下受控闭环：

```text
真实结果与用户反馈
→ Person Agent 反思
→ 提出“用户理解 / 上下文路由 / Prompt / Skill”变更建议
→ 用户确认或进入受控评审
→ 版本化生效
→ 继续观察结果，可回滚
```

第一版不允许 Agent 无审计地自动改写核心 Prompt、Skill、权限或长期记忆。任何自进化都要可追溯、可比较、可撤回。

## 5. 重要 Moment

重要 Moment 的本质不是发生了一件新鲜事，而是：

> 新事件或持续变化使 Person Agent 对用户至少一项重要理解需要重新评估，并可能要求 Elfred 改变后续支持方式。

候选 Moment 必须同时通过三道门：

1. 真实性：有足够独立证据证明变化存在；
2. 个人重要性：触及方向与动机、价值与身份、关系与角色、能力与身心状态、资源与环境条件之一；
3. 适应必要性：继续沿用旧理解会造成过时、冲突、低效或有风险的支持。

处理流程：观察变化 → Person Agent 合并证据 → 用户求证 → 用户确认/修正/搁置/否认 → 只向相关 Agent 分配最小必要上下文。

Moment 不自动创建任务，也不向所有 Agent 广播私人信息。

## 6. 页面框架

### 6.1 初始化

目标：以低认知负担形成足以产生首次个性化价值的初始上下文，并让用户理解信息边界。

- A/B Test：逐个 Agent 对齐 vs 多 Agent 群聊对齐；
- 两种体验必须共用同一信息、授权和记忆模型；
- 用户可跳过、修改、删除或标记不确定；
- 结束时展示“Elfred 当前理解了什么、哪些仍待确认”；
- 五个 Agent 的私有信息不能因为群聊初始化而自动互通。

### 6.2 首页

定位：用户与 Person Agent 核对“今日现实”的入口，不是 AI 功能陈列页。

用户应快速回答：今天最重要的是什么、现在进行得怎么样、我是否需要决定或行动。

#### 今日任务准入

候选事项需同时满足：重要性 + 今日相关性 + 行动必要性。任务分为用户任务和 Agent 任务，并按时间、注意力、隐私、费用、关系与现实后果进行风险分级确权。

#### 三时段卡

三张卡依次处理不同问题，而不是三次打卡：

| 阶段 | 作用 |
|---|---|
| 早间 | 确认今日任务、优先级和限制 |
| 中间 | 发现偏差，提出继续、缩减、替换、延期、求助或取消方案；用户确认后才能改安排 |
| 晚间 | 确认结果、原因、Person Agent 反思和延续事项 |

触发采用时间窗口 + 事件变化 + 用户主动三者结合，并逐步适配个人作息。

#### 晚间反思卡

Person Agent 的反思放入每日总结，不新增独立首页模块。卡片至少区分：

- 事实：今天发生了什么；
- 解释：偏差可能为什么发生；
- 理解：Person Agent 对用户形成了什么待确认的新理解；
- 行动：明日延续项、支持策略或最小上下文路由是否需要调整。

反思必须有依据和置信度。用户可确认、修正、搁置或否认；未经确认不得升级为稳定画像、广播给子 Agent或直接生成明日任务。

#### Agent 朋友圈

- 五个子 Agent 可基于自身信息源、记忆和职责发布文字、图片、视频、链接；
- 有真实触发和角色动机才发，不固定轮流刷屏；
- Agent 可评论其他 Agent 内容，但评论要补充、质疑或推进问题；
- 必须区分“我会的、我想的、我想做的、我感兴趣的”；
- 停留、点赞、收藏只形成弱信号；
- Person Agent 是否作为普通发帖主体仍是产品分歧，第一版不默认开放。

#### 任务播放器

播放器展示事实：已确认任务、Agent 执行状态和用户介入节点；中午卡负责判断是否偏离及如何调整。朋友圈内容拖入播放器后的含义仍未拍板，必须区分收藏、待处理、任务草稿和正式任务。

#### 首页待决策

- 三卡的精确字段、折叠与切换形式；
- 周/月汇总是否有独立价值；
- 五个 Agent 是否全部长期显示为首页按钮；
- “任务播放器”的名称和最终形态；
- 动态与社区是否继续共用首页切换。

### 6.3 社区

主体必须是真人，Agent 不伪装成社区用户。社区的特色方向是成为用户轻量化 vibe coding / AI 共创成果的展示和继续共创场所。

已形成的方向：Person Agent 可帮助真人发起共创帖，其他真人携带自己的 Agent 参与创作；各 Agent 在后台交换任务所需的最小信息，最终公开内容和承诺由真人确认。

仍需设计：什么条件下 Person Agent 可以建议生成私人草稿、草稿频率、谁能发起共创、共创帖结构、成果归属和治理。当前截图中的区域是“能力调用器”还是“共创工作区入口”仍属产品分歧。

### 6.4 知识页

定位：唯一负责跨天沉淀的主页面，让用户查看、理解和纠正长期记忆、知识、能力、Evidence 与 Outcome。

已确认边界：

- 能力必须追溯到真实 Evidence 与 Outcome；
- 用户可以纠正、隐藏、过期或删除记忆，但不能直接修改系统计算的能力分；
- 游戏卡式能力展示只是设计方案；
- Skill 等级、解锁节点和档数没有依据前不得写死；
- “知识/记忆/能力三入口”与“知识作为总容器”仍是产品分歧。

### 6.5 消息页

定位：真人关系与真人会话页面。消息列表只保留真人私聊和真人群聊；自己的 Person Agent 与五个子 Agent 不作为联系人。

Agent 是会话内仅本人可见的辅助层：

- 新好友破冰、久未联系恢复上下文、好友申请说明、关系淡化等场景降低社交摩擦；
- 私下恢复上下文、改写、翻译、检查风险和生成草稿；
- 群聊中总结未读、提取结论/分歧/任务/负责人/时间，整理共创素材；
- 所有对外发送、接受任务、承诺和长期记忆写入由真人确认。

A/B Test：仅 `@Agent` 唤醒 vs 可见快捷入口。被唤醒后的“半屏私密面板 / 虚化背景全屏 / 默认半屏可展开全屏”仍为讨论方案，不能写死。

### 6.6 我的页面

定位：管理“我是谁、别人如何看见我、Elfred 如何代表和保护我的身份”。

已确认属于本页：基本资料、隐私、账户、展示范围。私人记忆、聊天和任务默认不公开；系统生成的身份、能力和 Outcome 必须可追溯、可隐藏、可纠正。

“常规个人中心”与“可验证身份档案”仍是产品分歧，能力摘要和等级不得为了差异化无依据堆入页面。

### 6.7 右下角 Person Agent 入口

当前不在本轮页面设计和开发范围内。只保留位置与上下文接口，不能擅自补完整交互。

## 7. 跨页对象与红线

统一对象：弱信号、候选事项、任务草稿、已确认任务、运行状态、Evidence、Outcome、记忆、能力、身份投影。

必须遵守：

- 内容、收藏、点赞和停留不能自动成为任务；
- 普通聊天不能自动成为承诺或长期记忆；
- 对外发送、公开发布、付费、删除、敏感和不可逆操作必须人工确认；
- Agent 不能伪装真人或替代真人关系；
- 能力数字不能凭空生成；
- 当前产品没有“机会世界”页面，也没有六个 A2A 首页入口；
- 周报、月报、等级、解锁档数未验证前不能进入确定需求；
- 前端 Mock 必须明显是演示数据，不能伪装真实执行结果。

## 9. 开源项目与框架选型

### 9.1 当前结论

现阶段不应把任何 Agent 框架直接绑进前端。先保持前端通过稳定领域对象和适配器调用未来运行时。

| 项目 | 真实定位 | 对 Elfred 的价值 | 当前决定 |
|---|---|---|---|
| Letta / Letta Code | 有持久身份、分层记忆、Agent 级 Skill 和反思能力的有状态 Agent 体系 | 最贴合“每个 Agent 私有记忆和 Skill、跨时间学习”的需求 | 作为首选运行时与记忆 POC 候选；先验证隔离、可纠正、审计和成本，不直接写入前端 |
| OpenAI Codex | 本地/云端编码 Agent 与开发工具 | 用于读写代码、测试、重构和团队开发 | 作为开发工具，不作为 Elfred 产品内五 Agent 的运行框架 |
| EvoMap Evolver | 基于日志、Gene/Capsule/Event 产生可审计进化提示的自进化引擎；核心演进路线存在 source-available 转变 | 可参考版本化进化资产、事件审计、回滚与群体经验复用 | 只做后期自进化实验层，不承担第一版 Agent 运行时或通信总线 |
| LAAP | 强调持续自我模型、内在驱动、分层记忆和递归自我修改的数字生命概念/早期项目 | 可启发长期 Person Agent、自我连续性和反思研究 | 项目成熟度、仓库与工程接口仍需核验；不进入当前技术依赖 |
| Elys / ELY | 名称存在多个项目歧义；可确认的 ELY 方案强调本地/云模型路由、隐私脱敏和关键操作 HITL | 可参考隐私边界、关键操作确认和多模型路由 | 只吸收架构原则；在确认用户指的是哪个 Elys 前不做框架选型 |

### 9.2 推荐的分层架构

```text
Elfred 前端（当前仓库）
→ Elfred Domain/API Adapter（自行定义稳定契约）
→ Person Agent Orchestrator（路由、权限、反思、HITL）
→ 五个隔离的 Agent Runtime
→ 记忆 / Skill / 工具 / Evidence 存储
→ 可选 Evolution Lab（EvoMap/LAAP 类实验，不影响生产主链）
```

原则：产品模型和权限边界由 Elfred 自己定义，开源框架只能替换某一层，不能反向决定产品信息架构。

## 10. 当前前端工程基线

### 10.1 技术栈

- Next.js 16、React 19、TypeScript 5.9；
- Vinext/Vite 8 与 Cloudflare 适配；
- Lucide 图标、原生 CSS；
- 当前主要使用前端 Mock 与 `localStorage`；
- 后端、数据库、真实 Agent 调用不在本轮范围。

### 10.2 代码目录

```text
app/
├─ v27-7-state.ts            # 共享领域状态与本地持久化
├─ v27-7-data.ts             # 演示数据
├─ v27-7-app.tsx             # 兼容导出，禁止继续堆页面逻辑
└─ v28/
   ├─ page.tsx
   ├─ core/
   │  ├─ app-shell.tsx       # 页面组合、共享状态、底栏
   │  └─ screen.ts           # 导航契约
   ├─ features/
   │  ├─ home/
   │  ├─ knowledge/
   │  ├─ messages/
   │  └─ profile/
   └─ legacy/legacy-ui.tsx   # 待按业务域迁出的二级流程，禁止复制成两套实现
```

### 10.3 多人分工

- A：首页 + 消息，修改 `features/home/**`、`features/messages/**`；
- B：知识 + 我的，修改 `features/knowledge/**`、`features/profile/**`；
- C：`core/**`、共享状态、演示数据、测试、跨页契约与集成；
- 页面负责人需要 legacy 功能时，先明确归属，再由公共层迁出；
- 右下角 Person Agent 按钮暂不开发内部方案。

### 10.4 编码约束

1. 页面专属状态留在 feature；跨页对象进入共享领域层；持久化集中管理；
2. 同一概念只保留一个类型和一套状态，不在各页面复制；
3. Mock 数据与产品规则分离；
4. A/B Test 使用配置切换，共用数据模型；
5. 讨论项不得写死为默认公共逻辑；
6. 不新增旧版本路由壳、重复 CSS 和另一套视觉系统；
7. 编辑前检查工作树，保留其他人的修改；
8. 每次只迁移一个可验证业务切片，不一次重写全部 legacy；
9. 提交前运行 `npm run typecheck`、`npm test`、`npm run build`。

## 11. 第一阶段开发范围

目标不是一次完成所有产品，而是把当前框架变成可并行演进的前端骨架。

优先顺序：

1. 确认 `/v28?demo=1` 能稳定启动；
2. 让四个 feature 目录成为主页面唯一实现入口；
3. 抽出首页三时段卡、Agent 朋友圈、任务播放器组件；
4. 在晚间卡加入 Person Agent 反思的前端演示结构与确认/修正状态；
5. 抽出消息真人列表、真人会话和私密 Agent 面板；
6. 保持知识页和我的页面可独立探索，不提前写死产品分歧；
7. 建立共享类型、Mock fixture 和最小交互测试；
8. 每完成一个切片，运行类型、测试、构建门禁。

本阶段不做：真实后端、真实 Agent 框架接入、自动发帖、自动对外发送、自主改写 Prompt/Skill、周/月汇总、机会世界、六个 A2A 入口、右下角按钮完整方案。

## 12. 验收标准

- 新成员只阅读本文和对应页面方案，能说明产品主循环与页面边界；
- `/v28?demo=1` 可运行，四个主页面可到达；
- 首页能演示早间确认、中间校正、晚间总结与 Person Agent 反思；
- 任何推断进入长期记忆或分发给子 Agent 前都有用户确认；
- 消息列表没有 Agent 联系人分类，Agent 私密内容不会混入真人消息；
- 产品分歧仍保持可替换，没有被代码偷偷定版；
- `typecheck`、`test`、`build` 通过；
- 没有重新引入“机会世界”“六个 A2A 入口”等已废弃概念。
